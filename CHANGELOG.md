## [1.0.5] — 2026-05-22

**Python SDK + `--server` wiring completion + hardening bundle.** Three coordinated arcs in one PR; engineering backlog empty after this ships.

### Added

- **Python SDK at `python/`.** Thin sync subprocess + HTTPS wrapper around the rufio CLI. The SDK never reimplements substrate logic — every method shells out to the binary, so the CLI's `--json` is the single source of truth for record shape. Surface mirrors the 22-verb agent-participation set 1:1 (attend, think, observe, reason, retract, recall, confirm, refute, summon, accept, decline, say, leave, close, goal, goals_list, goal_complete, goal_abandon, open) plus `listen()` as a sync generator. Sync only; async is post-v1.0.5 scope.
- `internal/lib/client/sse.go` — shared SSE consumer used by both `rufio mirror sync` and `rufio listen --server`. Single source of truth for SSE decoding + TLS-by-default posture + bearer-attach.
- `internal/lib/serve/conn_counter.go` — per-token atomic counter for `/listen` concurrent connections (security audit M3).

### Changed

- **`--server` wiring is now uniform across all 22 agent-participation verbs.** Pre-v1.0.5 only 7/22 verbs functionally routed through `--server`; the remaining 15 fell through to local-mode-with-error. v1.0.5 wires reason, retract, summon, accept, decline, say, leave, close, goal, goals_list, goal_complete, goal_abandon, listen. The `TestRemoteWiringComplete_AllAgentParticipationVerbs` enumeration test (in `internal/lib/client/`) guards against future half-wires.
- `python/README.md` documents v1.0.5's intentional **no-PyPI-publishing** stance — install via `pip install git+https://github.com/d-mcmillan/rufio.git@v1.0.5#subdirectory=python`. The decision to publish is gated by a future maintainer-driven session before the v1.0.6 / public-launch arc.
- **Mirror file mode tightened from 0644 to 0600** (owner-only read+write) as a side-effect of the M4 unique-tmp-filename fix. `os.CreateTemp` creates files with 0600 mode and `os.Rename` preserves it; the previous `os.WriteFile(..., 0o644)` posture is gone. This is intentional defense-in-depth: a mirror is a per-agent shadow of substrate state and should not be group/world-readable by default. Operator tooling that previously read mirror files as a separate uid will need to adjust (chown the mirror dir, or run the tooling as the mirror owner). The on-disk substrate (under the server's root) keeps its existing mode contract.

### Fixed

- **Security audit N1 (defence-in-depth):** the wire-path prefix gate in `internal/lib/mirror/snapshot.go::projectRecordToFile` now operates on the CLEANED form of the wire path, not the raw form. Pre-fix, a hostile server emitting `path:"live/../.rufio/.mirror-cursor"` passed the raw `HasPrefix("live/")` check, then `filepath.Clean` resolved to `.rufio/.mirror-cursor` — wrote inside `--to` root but bypassed the "canonical substrate dirs only" intent (could clobber the mirror cursor file). New `validateCleanedTopLevel` helper in `safepath.go` enforces the cleaned-form check.
- **Security audit M2:** `/mcp` request bodies are now capped at 8 MB via `http.MaxBytesReader`. Pre-fix, a malicious client could stream gigabytes of body on a long-running POST and exhaust server memory before the per-request handler rejected it.
- **Security audit M3:** per-token cap of 32 concurrent `/listen` connections, enforced via an atomic counter keyed by token plaintext. The cap+1th connection gets `HTTP 429 Too Many Requests` with a `Retry-After` hint. Different tokens have independent counters.
- **Security audit M4:** `writeAtomic` in `internal/lib/mirror/snapshot.go` now uses `os.CreateTemp` for unique tmp filenames (`<target>.<random>.tmp`). Pre-fix, two concurrent writers to the same target both opened `<target>.tmp` for write, and the second's content overwrote the first's before either renamed — atomicity violated. Concurrent-writes-no-clobber regression guard in `m4_test.go`.
- **Audit-follow-ups (post-two-pass adversarial review):**
  - **H1 — N1 fix on `mirror sync` persistEvent.** The N1 cleaned-form top-level allowlist landed on the snapshot path but missed the live-sync path. A hostile server emitting `live/../.rufio/.mirror-cursor` over the `/listen` SSE stream would have bypassed N1 on the more commonly used long-running mode. Same `validateCleanedTopLevel` helper now gates both paths.
  - **H2 — Python SDK HTTPS scheme gate.** The Python listen path used `requests`/`sseclient` directly rather than subprocessing the CLI, so the Go-side `validateEndpointScheme` was bypassed. New `python/rufio/_security.py::_validate_endpoint_scheme` mirrors the Go helper byte-for-byte; called from `Rufio.__init__` (fail-fast on misconfig) and `RemoteListenStream._connect` (defense in depth).
  - **M1 — Bearer token via env, not argv.** Pre-fix the Python SDK emitted `--token <plaintext>` on argv; `ps -ef` + `/proc/<pid>/cmdline` are world-readable to the same uid, making the token visible to every sibling process. Now the token flows via `RUFIO_TOKEN` env (owner-only-readable on POSIX); the Go CLI already reads it from there.
  - **M2 — `writeCursor` unique tmp filenames.** The M4 fix landed on `writeAtomic` but missed the sibling `writeCursor` in `sync.go`. Two concurrent `rufio mirror sync` processes against the same `--to` raced on `<dir>/.mirror-cursor.tmp`. Same `os.CreateTemp` pattern now applied.
  - **M3 — Bounded error-body read on Python SSE failures.** Pre-fix, `RemoteListenStream._connect` sourced its non-200 error message from `self._response.text[:200]`, which reads the entire body before slicing. A hostile drip-feed would OOM the SDK. Now bounded at 4 KB via `iter_content`; connection closed immediately on error.
  - **L1 — Dead `maxBytesMiddleware` defer/recover removed.** `http.MaxBytesReader` signals over-cap reads via the Read error channel, not via panic; the defer/recover block was dead code AND a foot-gun (`rec.(error)` would panic on non-error recover values). Removed; the cap still works through the inner handler's body decoder.
  - **L3 — `connCounter.cells` map leak fixed.** Pre-fix, `release()` decremented the counter but never removed the cell entry. A long-running server accumulated a cell for every token it had ever seen. Now `release()` deletes the cell when its counter hits zero, with a re-check under the write lock to avoid racing a fresh acquire.
  - **F-NEW-4 — Local listen stderr deadlock.** Pre-fix, `Rufio.listen`'s local-mode `Popen` used `stderr=PIPE` with nothing reading the pipe. A CLI that wrote >64 KB to stderr blocked on stderr write → stopped emitting stdout JSONL → Python generator hung forever. Now `stderr=DEVNULL` (SDK doesn't surface CLI stderr anyway).
- **CRITICAL — channel-listen privacy floor.** Pre-fix, `rufio listen --types=channel-message` (and the equivalent MCP listen tool + `/listen` SSE + Python SDK listen generator) applied only scope-based privacy via `privacy.IsVisible`. `@channel-message` records carry no `scope` field — channel visibility is *membership*, not scope — so any authenticated identity could read every channel's messages on every listen surface. New `internal/lib/stream/channel_privacy.go` adds a `channelMembershipVisible` predicate keyed by `live/channels/active/<chID>/meta.gdl`; reuses `channels.IsEverMember` for past-member audit access; memoised per-call via `metaCache` (one disk read per channel regardless of message count). Wired into `passesAll()` — the single entry point every stream call site now routes through. 10 new tests across Go stream + Go SSE + Python SDK. **Lesson:** cross-surface privacy needs a per-record-TYPE predicate, not just `scope`; future audit gates must enumerate every record type's visibility primitive and assert enforcement on every read surface. Discovered post-`84f1bad`-merge via `claude -p` channel-validation sweep (Test 4: carol listens with `--types=channel-message`).
- **`recall --types=summon` JSON projection completeness.** `scanSummons` populated `Author`/`Subject`/`Intent` but dropped the on-disk `@summon` `to:` field entirely. SDK/MCP consumers of `recall --types=summon --json` had to re-parse the GDL `path` field to know who a summon was addressed to. Now mirrored to `RecallRecord.Target` (matching the existing convention for `@confirm`/`@refute`/`@retract`); surfaces as `target` in `RenderJSON` output. Regression guard: `TestScanSummons_TargetFieldPopulated`.
- **CRITICAL — TUI channel-privacy floor.** `internal/tui/watch_panes.go::InitialWalkPanes` and `consumePaneEvent` read channel metadata + messages directly from disk, bypassing the listen-surface predicate that the rest of v1.0.5 channel privacy is built on. A non-member running `rufio tui` saw every active channel (including private 2-party content) on the channels tab. Now both functions consult `channels.Channel.IsEverMember(me)` before emitting `ChannelMsg` / `ChannelMessageMsg` (matches the per-record-type predicate model used by `internal/lib/stream/channel_privacy.go`). Empty `me` (anonymous/test TUI) preserves firehose semantics to match the existing convention. Regression guard: `TestLoadTabs_ChannelsRequiresMembership_NonMember`. **Lesson reinforced:** every read surface — including TUI direct-from-disk walkers — needs the per-record-type predicate, not just the listen pipeline.
- **Post-review correctness loop (Pass 1 code review):**
  - **stream/channel_privacy.go `metaCache` correctness — mirror-sync arrival-ordering race.** Pre-fix, ANY `LoadMeta` failure inserted a `nil` sentinel hiding every subsequent event for that chID. On a mirror-sync receiver, `messages/<id>.gdl` can arrive before `meta.gdl` is visible — the first event's `LoadMeta` returns `*NoSuchChannelError`, the cache pins the chID as "permanently missing", and the listener loses visibility forever even after meta.gdl shows up. Fix: positive-only caching (failures NOT cached; one disk-stat per event for missing chIDs is acceptable given SSE round-trip cost). Regression guards: `TestMetaCache_TransientIOErrorNotCached`, `TestMetaCache_FailuresNotCached`.
  - **`recall.RecallRecord.Target` semantic overload — disambiguated to new `.To` field.** `Target` was load-bearing for `@confirm`/`@refute`/`@retract` (thought-id semantics); the v1.0.5 first-pass also wrote summon addressee into `Target`. A mixed-type recall (`--types=summon,refute`) would interleave `target=bob` (agent-id) and `target=t-...` (thought-id) under the same JSON key — SDK consumers de-referencing `target` as thought-id would silently misroute. Fix: new `RecallRecord.To` field for summon addressee; `RenderJSON` emits `to` (preserves on-disk @summon `to:` field name). `Target` is now strictly thought-id. Regression guard: updated `TestScanSummons_TargetFieldPopulated` asserts `To=bob` AND `Target=""` for summon records.
  - **`AllTypes` docs — `channel-message` is listen-only by design.** `rufio recall --types=channel-message` returns empty because channel-messages are live-only (under `live/channels/active/<ch>/messages/`, gated by membership in `channel_privacy.go`). The token stays in `AllTypes` so `--types=` validation accepts it uniformly across listen surfaces. Now documented inline with pointers to `rufio listen --catch-up --types=channel-message` / `rufio channel show`.
  - **`admin.ResolveToken` defense in depth — reject empty agent.** A corrupt `tokens.gdl` row (hand-edited / partial-write) with an empty `agent:` field would resolve to `currentAgent=""`, which `channel_privacy.go::channelMembershipVisible` treats as anonymous firehose — leaking every channel-message to that token's holder. `MintToken` validates at write time so this only fires under operator-induced corruption, but `ResolveToken` now rejects it explicitly rather than relying on every reader to re-check.

## [1.0.4] — 2026-05-22

**Hosted MVP.** Six MCP tools, HTTPS transport, mirror sync, security floor + audit closeout.

### Added

- `rufio serve` — HTTPS daemon hosting the MCP surface over `/mcp`, with a streaming `/listen` SSE endpoint for live event tail. Bearer-token auth; identity server-authoritative (clients never pass an agent id on the wire). `--insecure --bind=127.0.0.1` for localhost dev; TLS 1.3 required for any non-loopback bind.
- `rufio admin token mint --agent=<id>` / `revoke <id>` / `list` — bearer token lifecycle. SHA-256 hashes stored in `.rufio/.admin/tokens.gdl`; plaintext shown exactly once at mint time.
- `rufio mirror pull --from=<server> --to=<dir>` / `mirror sync --from=<server> --to=<dir>` — file-native client-side shadow of a remote substrate. Snapshot pull + continuous SSE-driven sync; atomic per-file writes; symlink-defence (security audit F4) on the `--to` root.
- `--server <url>` + `--token <plaintext>` global CLI flags — route any verb through a remote rufio server. v1.0.4 wired 7 verbs; v1.0.5 finishes the remaining 15 (see above).

### Fixed

- **Security audit (round 1, 2026-05-22):** L1 TLS 1.3 floor; L2 WWW-Authenticate header on 401; L3 token-prefix logging redaction; L4 case-insensitive Bearer scheme parsing; L5 TLS key permission check at startup; F1 cross-host redirect refusal + bearer-attach host gate; F3 per-tick token re-resolution on `/listen` for clean revoke; F4 symlink-aware mirror-root prefix check; F5 `%q`-quoted log fields against newline injection; H1 mirror wire-path traversal rejection; M5 client-side https:// scheme gate.
- **Security audit (round 2 / targeted, 2026-05-22):** Gate-5 UX `ErrSyncUnauthorized` abort after 5 consecutive 401s (instead of indefinite retry).

## [1.0.0] — 2026-05-14

**The v1 substrate is complete.** All 27 cognitive primitives + 5 daemon engines + TUI + demo orchestrator are operational. `mcp` adapter is the only deferred command (v1.1+).

### Changed

- **Implementation language: TypeScript/Bun → Go.** Week-1 functionality has been re-ported to Go. The TypeScript implementation is preserved at `legacy/typescript-week-1/` as the working spec. Single static binary built with `go build ./cmd/rufio`; ~10× lower daemon memory; faster cold start; native fit for the Bubble Tea TUI in week 3. CLI built on Cobra (Charm's Fang fell back to plain Cobra due to a transitive dep version skew, documented in `docs/followups.md` GO-P3-1).
- `fslock.LockError` renamed to `fslock.LockBusyError` and now satisfies the `RufioError` interface (`ExitCode() int { return 1 }`). Aligns with design §4.A error roster. Internal-only refactor; no public API surface affected (single call site inside fslock).

### Added

- `rufio init [name]` — scaffold a project with `given/`, `learned/`, `live/{outbox,inbox,attention,reasoning,summons/*,channels,goals/*}/`, `.rufio/{history,refs,snapshots,locks}/`, plus a default `rufio.gdl` carrying `@config + 3× @scope + 3× @retention`.
- `rufio push <path> [--stage=draft|staged|live]` — content-addressed blob storage (`.rufio/history/<2chars>/<rest-of-sha256>`, git-style fanout) with append-only Greppable refs (`.rufio/refs/<path>.gdl`). Versions are monotonic per path, assigned inside a per-path mkdir-lock (TOCTOU-safe). Path validation rejects traversal, `.rufio/`, `internal/`, `.git/`, and symlink escapes from the project root.
- `rufio pull <path>[@vN | @stage]` — fetch a versioned blob and write to stdout (binary-safe). Default selector is the latest `live`; `@v3` pulls a specific version; `@draft|@staged|@live` (or `--stage=`) pulls the latest of that stage. `--json` returns a single JSONL object with `{path, version, stage, sha256, ts, contentBase64}`.
- `rufio history <path>` — print every `@ref` for a path, latest-first. Default columnar (`<ts>  v<N>  stage:<s>  sha256:<short>  author:<a>  [rolled-back-from:vN]`). `--json` emits one JSONL object per ref, latest-first.
- `rufio diff <path>@v1 <path>@v2` — unified text diff between two versions of the same path. Both sides require explicit selectors. Identical content → empty stdout, exit 0. Binary content → "Binary files differ" message. In-house LCS-based line diff with `MaxDiffLines = 20000` guard; no external diff dependency.
- `rufio rollback <path>@<version>` — append a new version pointing at an older blob with `rolled_back_from:<old-version>` lineage. `--stage=` controls the rollback ref's stage (default `live`). Pure composition over `AppendRef`.
- `rufio dev` — foreground daemon. Watches `given/`, `learned/`, `live/outbox/` via `fsnotify`. Logs file events to stdout in the format `<ts>  <kind>  <path>` (POSIX form). Defines a hookable `EventHandler` interface — week 1 ships a no-op handler; week 2 plugs in cognitive-primitive routing without touching this file. SIGINT and SIGTERM trigger clean shutdown.
- **Tripwire test** (`test/integration/no_silent_stubs_test.go`) — mechanically enforces CLAUDE.md rule 1 ("no half-built features"). Every CLI command must either be in `implementedCommands` (real) or in `expectedStubs` (exits 2 with `not implemented yet (week N)`). A structural-drift test parses `internal/cli/stub.go` via `go/parser` and asserts the dispatcher's stub set equals `expectedStubs`. At v1.0 ship, `expectedStubs` MUST be empty.
- `rufio identity --as=<agent-id>` — persist an agent identity to `.rufio/identity.local.gdl` (gitignored via the `.rufio/` umbrella). Validates against `[a-z0-9][a-z0-9-]{0,63}`. Warns to stderr when `RUFIO_AGENT_ID` is set in env and differs from the persisted id (env wins over file at resolution time). `--json` emits `{"_type":"identity-set","_version":"1","agent":"<id>"}` — write-side, no source field.
- `rufio whoami` — print the current agent identity. Resolution order: `RUFIO_AGENT_ID` env > `.rufio/identity.local.gdl` > `NoIdentityError` exit 1. `--json` returns `{"_type":"whoami","_version":"1","agent":"<id>","source":"env|file"}`. Identity output is data — not suppressed by `--quiet`.
- **Identity package** (`internal/lib/identity/`) — the resolution + validation foundation for every cognitive primitive in weeks 2-5. Exposes `Validate(id)`, `EnvOverride()`, `ReadLocalFile(root)`, `WriteLocalFile(root, id)`, and `Resolve(root) (id, source, error)`. Persisted via Greppable `@identity|agent:<id>|set-at:<ts>` records; atomic write via `.tmp` + rename.
- `rufio attend --intent=<text> --entities=<csv> [--topics=<csv>]` — declare what the current agent is attending to. Writes a single `@attention|agent|intent|entities|topics?|ts` record to `live/attention/<me>.gdl` with wholesale overwrite (current-state semantics, design lock L2.3). Atomic via `.tmp + os.Rename` under the `.rufio/locks/attention-<agent>.lock` domain (5s default timeout → `*fslock.LockBusyError` exit 1). Entity ids must match `[a-z][a-z0-9-]*(:[a-zA-Z0-9_-]+)+`; topics (optional) must match `[a-z0-9][a-z0-9_-]*`. Identity resolved via `RUFIO_AGENT_ID` env > `.rufio/identity.local.gdl` > `*NoIdentityError` (exit 1). `--json` returns `{"_type":"attend-set","_version":"1","agent":"<id>","intent":"<text>","entities":[...],"topics":[...],"ts":"<rfc3339nano>"}`; topics is always an array (never null/absent).
- **Attention package** (`internal/lib/attention/`) — `ValidateIntent`, `ValidateEntities`, `ValidateTopics`, `BuildRecord`, `Write`, `WriteWithTimeout`. Shared between the write-side `attend` command and the (PR #21) read-side `rufio attention <id>` inspector.
- **Error types:** `InvalidContentError`, `InvalidEntitiesError`, `InvalidTopicsError` (all exit 2). Added to `internal/lib/errors/errors.go` and reusable by upcoming primitives (`think`, `observe`, `reason`).
- `rufio think --type=<...> --subject=<entity> --content=<text> --scope=<...> [--ttl=<seconds>] [--parent=<thought-id>] [--topics=<csv>]` — write an ambient thought to `live/outbox/<me>/<id>.gdl`. Append-only; each call produces a new `<unix-millis>-<rand6>` thought-id. Atomic via `.tmp + os.Rename` (no lock — unique id per call per design D5.9). For `--type=decision`, the same file additionally carries an `@context-bundle|decision:<id>|refs:<sha>,...` line capturing the SHA256s of every latest-live ref under `given/` and `learned/` (single atomic write, no orphan-bundle risk — design lock L2.9). Type enum: `hypothesis|observation|decision|question|focus` (note: `--type=observation` is fleeting/uncertain, *not* the durable `observe` record). Scope enum: `agent|deployment|fleet`. ### Fixed

- **e2e test fd-0 stomping (CI regression in PR #14)** — `os.NewFile(0, os.DevNull)` is wrong: `os.DevNull` is the `/dev/null` path string, NOT a file descriptor. The misuse wrapped fd 0 (stdin) in the parent test process; daemons spawned via these e2e tests inherited a shared *os.File whose finalizer eventually closed fd 0, corrupting subsequent tests' `t.TempDir()` cleanup (failing with `unlinkat ...: bad file descriptor`). Fixed in PR #14 across five files (`dev_retract_e2e_test.go`, `dev_routing_e2e_test.go`, `dev_autopromote_e2e_test.go`, `dev_ttlsweep_e2e_test.go`, `listen_test.go`). The new e2e test for summons (`dev_summon_e2e_test.go`) follows the correct `os.Open(os.DevNull)` pattern from day one. Closes WK3-AUTOPROMOTE-8.

### Locked decisions (carried over from week 1)

- Wire format: **Greppable** (`.gdl`, `.gdlm`, `.gdlc`, etc.). Spec at upstream `greppable/spec`.
- Exit codes: `0` success, `1` typed error (NoSuchVersion, NotInProject, AlreadyInitialised, EmptyRefs), `2` usage error (UsageError) / unknown flag.
- Strict `--quiet` rule: suppresses banners/summaries (chatter); never suppresses primary data (rows, blob bytes, diff text, daemon events).
- `--json` wins over `--quiet`: JSON output is data, never suppressed.
- Single-prefix invariant: `parseArgs` and command bodies throw bare-message `RufioError`s; `HandleError` is the single sink for the `rufio <cmd>: ` prefix.
