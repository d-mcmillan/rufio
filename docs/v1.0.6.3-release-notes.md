# Rufio v1.0.6.3 — TUI display fixes

**Patch on v1.0.6.2.** Fixes a few TUI display issues when running `rufio tui` without first starting the `rufio dev` daemon. Pure visual cleanup — no behaviour change, no surface changes.

## Highlights

The previous TUI rendered four "live"-implying indicators unconditionally, even when the file-watcher daemon was down — contradicting the truthful `· daemon offline ·` whisper already present in the substrate header. v1.0.6.3 gates each indicator on the existing daemon-online state:

- **Top header `syncing` spinner** is replaced with a quiet `· offline` tag when the daemon is down. Slot preserved; only the meaning changes.
- **Substrate panel sparkline + `N/s` rate are wired to real substrate event rate.** Previously decorative-only (a fixed sinusoid). v1.0.6.3 samples real events-per-second at 2 Hz from the TUI's fsnotify watcher (thoughts, confirms, attentions arriving on disk) and renders observed activity in the sparkline bars + N/s label. When the daemon is offline, the whole right-side segment suppresses (no events flow without the daemon).
- **Daemon-state detection now uses the heartbeat, not just the PID file.** Previously the TUI assumed the daemon was alive whenever `.rufio/locks/dev.pid` existed — which left the `live` indicator stuck when the daemon died ungracefully (SIGKILL, crash, OOM). v1.0.6.3 reads the existing daemon heartbeat (refreshed every 5s, stale at 30s) and only renders `live`-state when the heartbeat is fresh. Same signal `rufio dev --status` reports.
- **Mesh panel `live` badge** is suppressed when the daemon is down.
- **New bottom teaching hint** renders one Dim line above the keybind footer: `daemon offline — run \`rufio dev\` for live updates`. Converts a confusing UI moment into a teaching moment. Zero footprint when the daemon is up — height math is byte-identical to v1.0.6.2 for the daemon-up case.

When the daemon IS running, every indicator renders exactly as in v1.0.6.2 — zero regression for the user who runs `rufio dev` before `rufio tui`.

## Regression guard

New unit tests pin the gating semantics so future TUI work can't silently undo this fix. Real-terminal validation remains the visual-fidelity gate.

## Threat model — unchanged

Still **trusted-collaborator**: built for cooperatively-coordinating agent teams, not adversarial parties. Same posture as Postgres / Redis / git. Hardening for untrusted-party coordination remains on the v2 frontier.

Conservative v1.0.x pacing continues. Visual cleanup only — no paradigm shift.

- **v1.1.0 trigger:** "enterprise-evaluable" hosted Rufio (rate limiting, structured audit log, fine-grained scoping).
- **v1.2.0 gated on:** cryptographic identity, federation, multi-tenancy.

## Known limitations

- **TUI substrate-header truncation at narrow widths** can leak SGR parameter bytes as visible text. Visual nit only. Carried forward from v1.0.6.2.
- **Python SDK `recall()` empty-result shape** returns `[{}]` (one empty dict) instead of `[]` for zero records. Workaround: callers check `if records[0]`.
- **`recall --types=thought` does not surface `reason` records.** In deliberative scenarios across multiple agents, agents using `--types=thought` to "see what peers are thinking" may miss reasoning steps. Workaround: `--types=thought,reason`.

## Install

```bash
go install github.com/d-mcmillan/rufio/cmd/rufio@v1.0.6.3
```

Or build from source:

```bash
git clone https://github.com/d-mcmillan/rufio
cd rufio
go build -ldflags="-X main.version=v1.0.6.3" -o ~/.local/bin/rufio ./cmd/rufio
```

Python SDK:

```bash
pip install git+https://github.com/d-mcmillan/rufio.git@v1.0.6.3#subdirectory=python
```
