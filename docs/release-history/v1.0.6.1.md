# Rufio v1.0.6.1 — pre-public-launch polish bundle

**Patch on v1.0.6.** Five small fixes surfaced by a thorough pre-public-launch validation pass that drove the v1.0.6 binary through 9 cold-start scenarios (primer flow, goal/parent validation, recall reason linkage, thoughts privacy, retracted-marker, TUI scroll, MCP server, Python SDK, hosted serve). All five fixes are backwards-compatible additions or one-line corrections. Zero behavior regressions.

## What shipped

- **Banner double-`v` prefix fixed.** Pre-fix, the startup banner printed `vv1.0.6` because the format string included a literal `v` and the ldflag value also started with `v`. A new `normaliseVersion` helper in `internal/banner/banner.go` strips a single leading `v` defensively, so the banner is correct regardless of caller convention. Visible on every `rufio init`.
- **Quickstart card teaches the primary flag form.** Pre-fix, the card taught `confirm <id> --reason="..."` and `refute <id> --evidence="..."` — both inverted from each verb's primary flag. Now teaches the primary: `confirm <id> --evidence="..."` and `refute <id> --reason="..."`. The aliases (`--reason` on `confirm`, `--evidence` on `refute`) still work; the card just leads with the canonical form a cold agent should learn first.
- **Python SDK `recall()` accepts a positional query.** New signature: `recall(query: str | None = None, *, topics=..., types=..., since=..., scope=..., include_expired=False)`. Mirrors the CLI form `rufio recall "<query>"` exactly. Existing keyword-only call sites continue to work unchanged. Closes the cold-Python-agent footgun: the v1.0.6 primer teaches positional `recall "<subject>"` as the workaround for the topic-vs-subject trap, but the SDK pre-fix had no positional form — so a Python user following the primer hit `TypeError`.
- **Python SDK `observe()` accepts `object_=` as an alias.** Avoids shadowing the Python builtin `object`. Both forms are valid; if neither is passed, `ValueError`. Linters stop flagging, intuitive `object_=` writes don't fail.
- **Python SDK version bumped to 1.0.6** (`python/rufio/_version.py`) — was 1.0.5. Test cascade updated. The `python/README.md` install snippet was bumped from `@v1.0.5` to `@v1.0.6` in a follow-up.

## Provenance

- Validation pass: 9 cold-start scenarios + targeted fix verification.
- Code-review pass: clean, zero Critical, zero Major.
- Re-validation pass against the post-fix build: clean, all 5 fixes verified end-to-end + 9 regression scenarios pass.

## Known limitations

Same as v1.0.6 carry-over:

- **TUI substrate-header truncation** at narrow widths can leak SGR parameter bytes as visible text (width-naive truncation bisects ANSI escape sequences). Visual nit only, no data corruption.
- **Python SDK `recall()` empty-result shape**: returns `[{}]` (one empty dict) instead of `[]` when the CLI returns zero records. Pre-existing pre-v1.0.6 issue not introduced by this patch; will be addressed in v1.0.7.

## Versioning note

v1.0.6.1 is a patch release on v1.0.6 — no paradigm shift, no new substrate primitives, no transport surface changes. v1.1.0 trigger remains "Phase 2 enterprise-evaluable" (rate limiting, structured audit log, fine-grained scoping). v1.2.0 gated on Phase 3 (PKI / cryptographic identity / federation).

## Threat model — unchanged

Trusted-collaborator. Same posture as Postgres / Redis / git. Hardening for untrusted-party coordination remains v2 frontier.
