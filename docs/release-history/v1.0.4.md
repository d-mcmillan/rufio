# Rufio v1.0.4 — the hosted MVP

**The substrate, hostable.** Two agents on two different infrastructures coordinate securely through a hosted Rufio daemon, with a file-native local mirror preserved on every client.

This is the centerpiece release that proves Rufio's substrate-agnostic claim. The local contract from v1.0.x carries forward — agents still write GDL records to a directory — but now the directory can be on a server they reach via HTTPS, and the privacy floor holds end-to-end.

## What shipped

Six bundled threads:

- **`rufio serve --port=<n> --tls-cert=<path> --tls-key=<path>`** — HTTPS-MCP daemon exposing the 21-tool MCP surface to remote agents. TLS mandatory unless `--insecure --bind=127.0.0.1` (localhost dev only, loud stderr warning).
- **Bearer-token auth** — `rufio admin token mint --agent=<id>` issues tokens; SHA-256 hash stored on disk; plaintext shown EXACTLY ONCE. `rufio admin token revoke/list` complete the lifecycle. Token mint/revoke are NOT exposed via MCP (operator-only).
- **Server-side privacy enforcement** — every read path (`recall`, `listen`, `open`, `goals_list`, mirror) goes through `privacy.IsVisible` with the bearer token's resolved identity BEFORE bytes leave. The client cannot bypass.
- **`rufio mirror sync` + `rufio mirror pull`** — file-native local shadow of the remote substrate. Snapshot or continuous-SSE modes; atomic writes (.tmp + rename); cursor resume with exponential-backoff reconnect.
- **`rufio export` / `rufio import` `--format=jsonl`** — interop utilities for non-GDL pipelines (jq, pandas, BigQuery). JSONL is import/export ONLY; GDL stays canonical on disk.
- **`serve_status` MCP tool** — read-only health probe (root, token count, TLS hint).

## Provenance

This release implements **Phase 1 of the 4-phase hosted-rufio roadmap**. It proves the centerpiece launch claim: cross-org agents coordinate securely through a hosted daemon. Phase 2 (enterprise must-haves) is post-launch; Phase 3 (federation + cryptographic identity) is the v1.2 frontier.

## Versioning note

Conservative v1.0.x pacing continues — these are CLI surface additions plus a new transport variant, NOT a paradigm shift. The v1.1.0 trigger remains "Phase 2 enterprise-evaluable" (the next round of must-haves: rate limiting, structured audit log, fine-grained scoping). v1.2.0 is gated on Phase 3 (PKI / cryptographic identity / federation).

## Threat model framing — honest

**Research Preview.** v1.0.4 ships **trusted-collaborator** authentication: bearer tokens minted by a local operator, identity resolved server-side. This is sufficient for "one team runs the server, others bring tokens" topologies (Slack-trust).

**PKI / cryptographic identity / federation is the v1.2 frontier.** Production deployments outside trusted-collaborator settings should wait for v1.2. The release ships honest documentation around this in [docs/hosted.md](./hosted.md).

## Quickstart (hosted mode)

```bash
# 1. Set up the server
mkdir /var/lib/rufio && cd /var/lib/rufio
rufio init my-org
openssl req -x509 -newkey rsa:2048 -keyout key.pem -out cert.pem -days 365 -nodes -subj "/CN=rufio.example.com"
TOKEN=$(rufio admin token mint --agent=alice | grep ^token= | cut -d= -f2)

# 2. Start the server
rufio serve --port=8443 --tls-cert=./cert.pem --tls-key=./key.pem &

# 3. From any client machine
export RUFIO_SERVER=https://rufio.example.com:8443
export RUFIO_TOKEN="$TOKEN"
rufio attend --intent="testing" --entities=test:1
rufio think --type=hypothesis --subject=test:1 --content="alpha" --scope=fleet
rufio recall --topics=alpha

# 4. Keep a local file-native mirror
rufio mirror sync --to=./my-mirror &
```

Full operational guide: [docs/hosted.md](./hosted.md).

## What's next

**v1.0.5: Python SDK.** Local + remote transports parity. Same agent identity, same JSON shapes, same privacy floor. Brings Rufio into harnesses that don't shell well.

**v1.1.0 (Phase 2): enterprise-evaluable.** Rate limiting, structured audit log, fine-grained scoping, hosted onboarding flow.

**v1.2.0 (Phase 3): the frontier.** PKI / cryptographic identity / federation across organizations. Trust model upgrades from "trusted-collaborator" to "verifiable-counterparty".
