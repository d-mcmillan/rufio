# Rufio v1.0.3 — onboarding + propagation polish

**One command before they know what else exists.** `rufio quickstart` prints the locked sub-200-token-ish cold-start card teaching the seven first-contact verbs, quorum dynamics (≥3 confirmers at ≥0.85 → auto-promote), and the load-bearing subject-vs-topics distinction. `rufio init` folds the same card into existing `CLAUDE.md` / `.cursorrules` / `AGENTS.md`. A new MCP tool exposes the card over the MCP transport. The cold-start anchor every vet round asked for.

Alongside the onboarding bundle: the propagation surface gets richer. `@auto-promote` audit records now carry the full quorum dynamics — confirmers, counts, confidence, scope — and surface as enriched events on `rufio listen --catch-up`. TUI and third-party watchers see the propagation state without a separate read. Privacy floor honored end-to-end.

## What shipped

- **`rufio quickstart`** — prints the locked cold-start card. No project root required; bootstraps a cold agent BEFORE they have one. `--json` emits `{_type:"quickstart",_version:1,content:<card>,card_version:1}`.
- **`internal/lib/quickstart/`** — owns `CardV1` + `CardVersion`. Single source of truth for the CLI verb, the MCP tool, and the init fold.
- **`rufio init` scaffolding extension** — folds the locked card into existing harness files inside `<!-- rufio:quickstart-card v1 -->` ... `<!-- /rufio:quickstart-card -->` markers. Coexists with the primer fold (separate marker pair, separate evolution path). Idempotent; never CREATES harness files the user didn't have.
- **MCP tool: `quickstart`** — the card over the MCP stdio transport. Byte-structural fidelity with `rufio quickstart --json` enforced by shared package constants.
- **Enriched auto-promote stream events** — the `@auto-promote` record now carries `version`, `origin`, `subject`, `scope`, `confirmers`, `confirm-count`, `refute-count`, `confidence` alongside the legacy thought/observation/by/ts fields. Schema LOCKED at `AutoPromoteEventVersion=1`; future enrichments bump the version, never rename fields. `stream.Event` grows optional auto-promote fields (omitempty); `live/promoted/` added to listen's walk dirs.
- **Privacy floor on auto-promote events** — scope=agent promotions are visible only to the original author on the stream. Same predicate (`privacy.IsVisible`) every other read surface goes through; the enriched record's `origin` field is what makes the visibility check correct (the literal `by:auto-promote` is the daemon's identity, not the human-author identity the floor needs).
- **`rufio think --help` documents `--type`** — the flag and its enum alternatives were already present on the v1.0.2 branch; this release locks the contract with a regression test so the cold-start round 7 regression can't recur silently.
- **Positioning copy refresh** — removed "deliberately local" / "Local-only" framing from `docs/v1.0.1-release-notes.md` + `docs/roadmap.md`. Replaced with the locked threat-model positioning: distributed cognition across heterogeneous agents, cross-infrastructure substrate today via shared filesystem or MCP, with cryptographic identity + storage-layer enforcement on the v2 frontier. A tripwire test pins the lock. CHANGELOG historical entries deliberately untouched — immutable audit trail.
- **CHANGELOG catch-up** — `v1.0.2` + `v1.0.3` entries added; mirrors the Keep-a-Changelog Added/Fixed/Changed style.

## Provenance

Two cross-harness sessions produced the v1.0.3 anchor:

- **Cross-harness consensus** — the cold-start quickstart card was decided by 4/4 agents reaching quorum on the load-bearing primacy of the card before adding more runtime verbs.
- **Enriched auto-promote payload** — surfacing confirmers / counts / confidence on the wire lets TUI + third-party watchers display real quorum state without a separate read.

## Versioning note

Same conservative pacing as v1.0.2: this is a v1.0.x polish release, not a v1.1.0 minor bump. MINOR bumps are gated on real paradigm-shift triggers (Python SDK landing → v1.1.0; cryptographic identity / hosted mode → v1.2.0+).

## Threat model — unchanged

Still **trusted-collaborator**: built for cooperatively-coordinating agent teams, not adversarial parties. Hardening for untrusted-party coordination remains on the v2 frontier.

## Quickstart for the new verb

```
go install github.com/d-mcmillan/rufio/cmd/rufio@v1.0.3
rufio quickstart                    # print the card; no project required
rufio quickstart --json | jq        # machine path
mkdir my-substrate && cd my-substrate && rufio init
echo "# claude config" > CLAUDE.md && rufio init    # folds card into existing file (idempotent)
```

## Auto-promote propagation in action

```
RUFIO_AGENT_ID=alice rufio attend --intent="alpha" --entities=test:1 --scope=fleet
RUFIO_AGENT_ID=alice rufio think --type=hypothesis --subject=test:1 \
                                  --content="seed" --scope=fleet --topics=alpha
THOUGHT_ID=$(RUFIO_AGENT_ID=alice rufio recall --topics=alpha --json | jq -r '.[0].id')
RUFIO_AGENT_ID=bob   rufio confirm "$THOUGHT_ID" --reason="agree"
RUFIO_AGENT_ID=carol rufio confirm "$THOUGHT_ID" --reason="agree"
RUFIO_AGENT_ID=dave  rufio confirm "$THOUGHT_ID" --reason="agree"
RUFIO_AGENT_ID=eve   rufio listen --catch-up --types=auto-promote
# → emits one JSON line per auto-promote event with the full quorum payload:
#    {_type:"auto-promote", _version:1, source_thought_id, promoted_id,
#     subject, confirmers, confirm_count, refute_count, confidence, ...}
```
