# Rufio v1.0.6.2 — Polish, docs, and quality cleanup (round 2)

**Patch on v1.0.6.1.** Five small fixes surfaced by fresh-install walkthroughs of the install + first-run experience, plus a long-running multi-agent cognition demo (the substrate held context across hours of cross-agent reasoning on a hard philosophical question). All fixes are backwards-compatible additions or doc corrections. Zero behavior regressions.

## Highlights

- **`rufio recall --types=goal` now actually surfaces goals.** Previously the `goal` type was advertised in the filter enum but the recall scanner had no code path for `live/goals/`. Cold agents writing a goal and then trying to recall it saw nothing. Fixed: scanner added; positional substring search and entity-id exact match both work; the privacy floor is enforced (other-agents' `scope:agent` goals invisible).
- **Install snippets corrected.** All documented install commands now pin to the polished tag (`@v1.0.6.2`). A previous version of the README pinned to the pre-polish tag, so following the install path got users the older (buggier) binary.
- **Primer teaches the right entity-id form on first contact.** Documented examples like `--entities=freewill` were rejected by the CLI (which requires `namespace:local` form). The primer now uses `topic:freewill`, `customer:5821`, etc. and explicitly states bare tokens are rejected.
- **Primer documents the reason-on-hypothesis workaround.** Previously the primer pointed agents at `rufio reason --decision=<id>` even when the id pointed at a hypothesis; the CLI rejects that. Now teaches both alternatives: `think --type=hypothesis --parent=<id>` for in-flight refinement, or elevate-to-decision-first when committing to a chain of reasoning.
- **Status section reframed.** README dropped "public research preview" language in favor of "v1.0.x — substrate primitives stable, frontier evolving" — the version number does the maturity signaling work.

## New regression guard

A new integration test extracts every `rufio` command from the generated primer (`RUFIO.md`) and execs each one against a real init-ed project. Any future primer edit that drifts a documented command from the CLI parser/validator semantics will fail CI loudly. This is the kind of test that prevents future doc-vs-CLI surprises.

## Threat model — unchanged

Still **trusted-collaborator**: built for cooperatively-coordinating agent teams, not adversarial parties. Same posture as Postgres / Redis / git. Hardening for untrusted-party coordination remains on the v2 frontier.

## Versioning note

Conservative v1.0.x pacing continues. These are polish and quality fixes — not a paradigm shift.

- **v1.1.0 trigger:** "enterprise-evaluable" hosted Rufio (rate limiting, structured audit log, fine-grained scoping).
- **v1.2.0 gated on:** cryptographic identity, federation, multi-tenancy.

## Known limitations

- **TUI substrate-header truncation at narrow widths** can leak SGR parameter bytes as visible text. Visual nit only.
- **Python SDK `recall()` empty-result shape** returns `[{}]` (one empty dict) instead of `[]` for zero records. Workaround: callers check `if records[0]`.
- **`recall --types=thought` does not surface `reason` records.** In deliberative scenarios across multiple agents, agents using `--types=thought` to "see what peers are thinking" may miss reasoning steps. Workaround: `--types=thought,reason`. Design decision for the next release.

## Install

```bash
go install github.com/d-mcmillan/rufio/cmd/rufio@v1.0.6.2
```

Or build from source:

```bash
git clone https://github.com/d-mcmillan/rufio
cd rufio
go build -ldflags="-X main.version=v1.0.6.2" -o ~/.local/bin/rufio ./cmd/rufio
```

Python SDK:

```bash
pip install git+https://github.com/d-mcmillan/rufio.git@v1.0.6.2#subdirectory=python
```
